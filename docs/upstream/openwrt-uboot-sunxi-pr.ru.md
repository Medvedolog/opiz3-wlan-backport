# PR в OpenWrt: U-Boot 2026.04 для плат H616/H618 на 1,5 ГБ и исправление YT8531 после тёплой перезагрузки

[English version](openwrt-uboot-sunxi-pr.md)

Готовый текст pull request в [openwrt/openwrt](https://github.com/openwrt/openwrt)
(пакет `uboot-sunxi`) и что проверить перед отправкой. Для самого U-Boot
есть отдельный черновик: [uboot-yt8531-power-down.md](uboot-yt8531-power-down.md).
Текст PR — на английском: так принято в OpenWrt.

## Коротко

- **Платы на 1,5 ГБ.** В OpenWrt 25.12.x стоит U-Boot 2025.01. Он умеет
  определять только объём памяти, равный степени двойки, поэтому Zero 3 и
  Zero 2W на 1,5 ГБ не загружаются. Поддержка появилась в U-Boot v2026.04
  (коммит c47b636737).
- **Ethernet после тёплой перезагрузки.** Начиная с U-Boot v2025.04, U-Boot
  перестал сбрасывать PHY при старте (коммит bab54f5942). Linux при
  выключении eth0 переводит YT8531 в режим сна, тёплая перезагрузка его не
  будит, и следующее ядро падает с «EMAC reset timeout» до выключения
  питания. В 2025.01 сброс ещё был, поэтому старый U-Boot работает с
  Ethernet, но не с 1,5 ГБ, а новый — наоборот.
- Проект собирает для H618 U-Boot v2026.04 с возвращённым сбросом
  (`uboot/patches/001-net-phy-reset-the-PHY-on-connect.patch`), проверено
  на железе.

## Перед отправкой

1. **Подпись.** `Signed-off-by:` с настоящим именем и почтой.
2. **Порядок.** OpenWrt обычно ждёт исправления сначала в U-Boot. Проверьте
   на плате вариант B из [uboot-yt8531-power-down.md](uboot-yt8531-power-down.md)
   (снятие `BMCR_PDOWN` только в драйвере Motorcomm), отправьте его в
   `u-boot@lists.denx.de` и сошлитесь на это письмо в PR.
3. **Охват.** Обновление `uboot-sunxi` касается всех плат sunxi, мейнтейнеры
   спросят про это. Либо проверьте больше плат, либо ограничьте новую
   версию платами H616/H618, как в CI проекта.
4. **Коммиты.** Отдельно обновление версии, отдельно патч; сообщение
   коммита — сокращённое описание PR ниже.

## Почему так получилось (подробно)

1. При выключении Linux опускает eth0, phylib усыпляет PHY: выставляется бит
   `BMCR_PDOWN`.
2. При тёплой перезагрузке питание с PHY не снимается, и U-Boot получает
   его спящим.
3. До v2025.01 функция `phy_connect_dev()` делала `phy_reset()`, и сброс
   снимал `BMCR_PDOWN`. Коммит bab54f5942 этот сброс убрал намеренно
   (некоторые PHY нельзя сбрасывать до загрузки их драйвера). Драйвер
   YT8531 (`yt8531_config()` → `genphy_config_aneg()`) бит не трогает, и
   PHY остаётся спящим.
4. Без тактового сигнала RX от PHY программный сброс DMA в stmmac не
   проходит: `dwmac-sun8i 5020000.ethernet: EMAC reset timeout`, открытие
   интерфейса падает с `-110`. По MDIO PHY при этом отвечает.

Проверено на Orange Pi Zero 3 (1 ГБ и 1,5 ГБ), OpenWrt 25.12.5, Linux 6.12,
U-Boot v2026.04 с патчем, TF-A v2.10: плата на 1,5 ГБ загружается; после
нескольких тёплых перезагрузок с кабелем eth0 поднимается на 2,6 с, линк на
5,7 с, без «EMAC reset timeout»; без патча каждая тёплая перезагрузка
заканчивается этой ошибкой. Не проверено: другие платы H616/H618 с другими
PHY (например, RTL8211F на Zero 2).
